Dev Guide MEAL PLAN
Page load — one query, not 21
GET /api/meal-plans/current // Returns full week with all slots + templates // One DB query with JOIN — never fetch per-slot Response: { id, week_start, slots: [{ id, day_of_week, meal_type, is_eatout, template: { id, dish_name, tags[], avg_kcal, prep_minutes } }] } PATCH /api/meal-plans/:id/slots // Assign template to a slot Body: { day_of_week: 3, meal_type: "lunch", template_id: "uuid" } 200: { slot: { id, template } } PATCH /api/meal-plans/:id/slots // Set eat-out slot Body: { day_of_week: 3, meal_type: "dinner", is_eatout: true, template_id: null } POST /api/meal-plans/copy-last-week // Duplicates last week's plan for current week // Returns 404 if no previous week exists — handle gracefully POST /api/meal-plans/auto-fill // Fills empty slots with recommended templates // Based on user's goal + diet_type + household_size Body: { fill_empty_only: true } // never overwrite assigned
Cart action from meal plan
POST /api/cart/build // Build Instamart cart from today's assigned slots Body: { slot_ids: ["uuid1", "uuid2"], date: "2026-07-02" } // Returns ingredient list, not a placed order // User must confirm in Cart Preview screen
Tables used on this screen
meal_plans id, user_id, week_start DATE meal_plan_slots id, meal_plan_id day_of_week INTEGER // 1=Mon … 7=Sun meal_type ENUM(breakfast,lunch,dinner) template_id UUID // nullable is_eatout BOOLEAN // default false templates // read-only on this screen id, dish_name, avg_kcal prep_minutes, tags[] UNIQUE constraint: (meal_plan_id, day_of_week, meal_type)
Optimised Drizzle query
// Get full week in ONE query — no N+1 const plan = await db.query.mealPlans.findFirst({ where: and( eq(mealPlans.userId, userId), eq(mealPlans.weekStart, weekStartDate) ), with: { slots: { with: { template: true } // single JOIN } } })
Prevent these
  • N+1 on slots: Never query each slot's template individually. One JOIN query for the full week — always.
  • Copy last week → no previous plan: API returns 404. UI must show "No previous week to copy" inline, not an error toast.
  • Auto-fill overwrites: Auto-fill must only fill EMPTY slots (template_id IS NULL and is_eatout = false). Never replace an already-assigned meal.
  • Duplicate slots: The DB UNIQUE constraint on (meal_plan_id, day_of_week, meal_type) prevents this. But the API must return a clear 409 — not a 500.
  • Week start timezone: week_start must be Monday in the user's local timezone. Server-side: always compute from a client-supplied date string, not server UTC.
  • Drag-and-drop: Never send one PATCH per cell during drag. Collect the full new state and send a single PATCH at drop. Otherwise a slow connection leaves the DB in a broken intermediate state.
  • Eat-out slot + template both set: Validate server-side that if is_eatout=true, template_id must be null. One or the other.
Auth & row-level security
  • All PATCH requests verify the meal_plan belongs to the authenticated user before updating. Never trust plan ID from URL alone.
  • Template IDs in PATCH body must be validated: confirm the template is public OR belongs to the user. Never allow assigning another user's private template.
  • Auto-fill: the recommendation engine runs server-side with the user's goals from the DB. Never pass goal/diet from the client body — read from JWT user record.
Rate limits
PATCH /api/meal-plans/:id/slots 60/min POST /api/meal-plans/auto-fill 5/min POST /api/cart/build 10/min
Swiggy DS — grid rules
  • Today column: 3px orange top border on the header cell only. Column bg: rgba(252,128,25,.02) — barely visible, just enough context. No orange on the cells themselves.
  • Empty slot: Dashed border + plus icon + "Add meal" in muted colour. Never leave a white empty box — that reads as broken.
  • Assigned slot: Solid 1px #E9E9EB border. Meal name bold 11.5px charcoal. Kcal + time in 10px muted. "Change" link appears on hover only.
  • Eat-out slot: #FFF8F2 background, orange icon circle, "Eat out" in orange 10px bold. Never use orange fill on the full cell — only the icon circle.
  • Picker panel: Replaces the nutrition panel when a slot is clicked. Never use a modal — the grid must stay visible so users know which slot they are editing.
  • Auto-fill button: Primary orange CTA. This is more important than "Copy last week". Position it rightmost in the action row.
  • Mobile: Grid not shown. One day at a time via tab strip. Three stacked cards per day. "Add all to Instamart" fixed at the bottom of the day view.
  • Picker filter chips: Default selected = "All". Only one active at a time. Not multi-select.
