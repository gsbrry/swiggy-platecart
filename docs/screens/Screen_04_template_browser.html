Dev Guide TEMPLATE BROWSER
Lane loading — staggered, not all at once
// Load "For You" lane first on mount GET /api/templates?lane=foryou&limit=8 // Personalised: uses auth user's goal + diet_type // Returns templates sorted by relevance score GET /api/templates?lane=popular&limit=8 // Sorted by fork_count DESC, last 7 days GET /api/templates?lane=quick&prep_max=15&limit=8 GET /api/templates?lane=protein&min_protein=20&limit=8 // Search — debounced 300ms, min 2 chars GET /api/templates?q="dal"&limit=20&cursor=uuid // Filter chips change the query params GET /api/templates?diet=veg&limit=8&lane=foryou // Fork a template POST /api/templates/:id/fork 201: { forked_template_id, fork_count } // Add to meal plan slot (from browser) PATCH /api/meal-plans/current/slots Body: { template_id, day_of_week, meal_type }
Pagination — cursor-based
// Never use offset pagination — breaks on inserts // Use cursor (last item's ID) for "See all" + search Response: { templates: [...], next_cursor: "uuid", // null if no more total_count: 340 } // Load more: pass cursor from previous response GET /api/templates?q="dal"&cursor="last-uuid"
Templates table — key fields for this screen
templates id, creator_id, dish_name tags text[] diet_type ENUM avg_kcal integer prep_minutes integer protein_g integer // for high-protein filter fork_count integer buy_count integer // times added to Instamart is_public boolean // false = only creator sees created_at timestamp // No "likes" or "ratings" — fork_count IS the trust signal // buy_count is secondary: "bought 847 times" matters more
Relevance scoring for "For You" lane
// Server-side scoring (not exposed to client) score = fork_count * 0.4 + (diet_match ? 30 : 0) + (goal_tag_match ? 25 : 0) + (kcal_in_range ? 20 : 0) + recency_boost // decays over 30 days // Never expose the scoring formula to the client
High-impact mistakes
  • Loading all 340 on mount: The browser will load "For You" lane (8 items) first, then lazy-load other lanes as the user scrolls. Never fetch all templates on mount.
  • Offset pagination: If a new template is added between page 1 and page 2 fetches, offset pagination shows duplicates. Use cursor-based pagination.
  • Search on every keystroke: Debounce search at 300ms minimum. Minimum 2 characters before triggering. Short searches on a 340-row table with full-text index are still expensive at scale.
  • Fork count stale: Fork count is an optimistic update on the client (increment immediately on click). Sync to server in the background. Never wait for the API before showing the updated count.
  • Filter chips reload all lanes: Applying a filter should re-fetch only the active lane, not all 4 simultaneously.
  • Horizontal lane overflow: Always set overflow-x:auto on lanes and scrollbar-width:none. Never let the lane overflow the viewport width.
Visibility rules
  • Public templates (is_public=true): readable without auth. Safe to cache at edge (Vercel CDN).
  • Private templates: only returned if auth user's clerk_id matches creator_id. Never include in public lane responses.
  • Fork endpoint: requires auth. Validate the source template is public or belongs to the user before creating a fork.
  • Creator info: only expose display_name. Never expose email, clerk_id, or full name in template responses.
Rate limits
GET /api/templates 200/min anon, 500/min auth GET /api/templates?q=* 60/min — search is expensive POST /api/templates/:id/fork 20/min per user
Swiggy DS — template browser rules
  • Lanes are the default view. Grid view is opt-in via toggle. Most users will never switch — don't make grid the default.
  • Card thumbnail: Monotone icon on var(--pg) background. No food photos in v1 — they require a CDN, moderation, and upload flow. Add in Phase 2 once templates have community traction.
  • Partial next card: Each lane scroll must clip the last card at ~70% to signal there's more. Achieved by setting lane-scroll overflow-x:auto with no padding-right.
  • Fork count: Primary trust signal on every card. More prominent than kcal. Show as "⑂ 1,204" using the fork icon. Buy count is secondary: shown only on detail page.
  • "Add to plan" micro-dropdown: Opens inline, positioned relative to the card. Never navigate away from the browser to assign a template.
  • Diet dot on card thumbnail: Small 8px circle, green for veg, charcoal for non-veg. Not a chip — chips are for the card body.
  • Search results: Switch to grid view automatically. Lane view with filtered results doesn't make UX sense.
  • Filter chips: Only one active at a time. They filter all lanes simultaneously — they do not open a new page or modal.
