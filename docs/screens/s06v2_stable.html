Dev Guide CREATE TEMPLATE
Ingredient search — Instamart catalog
// Search as user types — debounced 250ms GET /api/ingredients/search?q="spinach"&limit=8 Response: [{ id, name, default_unit: "g", instamart_sku: "SKU_12345", kcal_per_100g: 23, protein_per_100g: 2.9, in_stock: true }] // Nutrition auto-calc — triggered server-side POST /api/templates/calculate-nutrition Body: { ingredients: [{id, qty, unit}] } Response: { kcal, protein_g, carb_g, fat_g, est_cost_inr, suggested_goal_tags: ["loss", "light"] }
Save draft vs Publish
// Save draft — localStorage only, no DB write localStorage.setItem('template_draft', JSON.stringify(formState)) // Publish — creates the DB row POST /api/templates // auth required Body: { dish_name, meal_type, diet_type, prep_minutes, default_servings, is_public, goal_tags[], ingredients: [{ingredient_id, qty, unit}], instructions: [{step_number, text, tip}] } 201: { id, slug } // Redirect to /templates/:slug after publish PATCH /api/templates/:id // Edit existing template (only creator)
Ingredient catalog — separate from template ingredients
ingredients // master catalog, read-only for users id, name default_unit text instamart_sku text // links to Instamart item kcal_per_100g numeric protein_per_100g numeric carb_per_100g numeric fat_per_100g numeric updated_at timestamp template_ingredients // user's recipe quantities id, template_id ingredient_id // FK to catalog — never free text qty_per_serving NUMERIC unit text // Nutrition is NOT stored on template_ingredients // It's always calculated from catalog at query time // This way, if Instamart updates a product's nutrition, // all templates using it auto-update
Critical implementation mistakes
  • Free-text ingredients break cart-build. Every ingredient must be selected from the catalog (autocomplete dropdown). Never allow free text that doesn't map to an ingredient_id — it will cause cart/build to fail silently.
  • Client-side kcal calculation is wrong. Do not calculate nutrition in the browser. Call /api/templates/calculate-nutrition. The nutrition database handles unit conversions (1 tsp ghee → grams → kcal). Client math will be off by 20–40%.
  • Auto-save to DB is expensive. Draft auto-save goes to localStorage every 30s. Only write to DB on explicit Publish or manual "Save draft" click. A user starting a template and closing the tab should not create a DB row.
  • Publish without minimum fields. Publish button is disabled unless: dish_name is filled, meal_type is selected, diet_type is selected, at least 2 ingredients are added, prep_minutes is filled. Enforce both client-side and server-side.
  • Instructions order breaks on edit. Instructions are ordered by step_number. When a step is deleted, renumber remaining steps in the same PATCH call — never leave gaps (1, 3, 4) in step_number.
  • Duplicate ingredient rows. If a user adds "spinach" twice, merge the rows server-side and show a toast "Combined 2 spinach entries". Two rows of the same ingredient breaks cart deduplication.
Ownership and trust
  • On publish: set creator_id = auth user's ID from JWT. Never from request body.
  • PATCH /api/templates/:id: verify req.user.id === template.creator_id before any update. Return 403 otherwise.
  • est_cost_per_serving: read-only field. Calculated server-side from live Instamart prices. A creator cannot set their own cost — it would be misleading.
  • Nutrition values: same as cost — calculated server-side from the catalog, never from user input. Prevent creators from falsely claiming "50 kcal" on a calorie-dense dish.
  • Moderation: Phase 1 — no moderation. Add a report function. Phase 2 — flag templates with suspicious nutrition values (>2000 kcal for a single meal) for review.
Swiggy DS — create template rules
  • Live preview is the reward signal. As the user types the dish name, the preview card on the right updates in real-time. This is what keeps creators engaged — they can see the result forming.
  • Ingredient row layout: [search input — flex:1] [qty — 80px] [unit select — 90px] [delete — 32px]. All on one row. Never stack them vertically — it makes the list feel long.
  • Autocomplete dropdown: Shows ingredient name + "On Instamart" badge in green. If the ingredient is not in the catalog, show "Add to catalog request" option. Never allow free text selection.
  • Est. cost per serving: Read-only field with a "auto" placeholder. Show a tooltip "Calculated from live Instamart prices". Never editable — trust is built on accurate pricing.
  • Goal tag auto-suggest: After nutrition is calculated, show "Auto-tagged: Weight Loss" in the preview panel. User can override by deselecting chips.
  • Publish button: Disabled state = grey fill, "not enough info" status text. Enabled = orange fill. Never show a red disabled state — it reads as an error.
  • Draft save status: "Draft saved" appears in the page header with a green check. Auto-clears after 3 seconds. Never a persistent status label that takes space.
  • Mobile: Single column, chip selectors for meal type and diet type (not dropdowns — chips are faster to tap). Ingredients shown as a compact list, not a full row editor.
