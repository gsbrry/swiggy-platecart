Developer Guide DASHBOARD
API Calls on Page Load
GET /api/user/profile // Clerk JWT in Authorization header // Returns user's goal, budget, diet type Response: { id, name, goal, diet_type, monthly_budget, household_size, eatout_per_week, exclusions[] } GET /api/meal-plans/current // Today's slots only — do NOT fetch all 7 days Response: { week_start, id, slots: [{ day_of_week, meal_type, template: { dish_name, tags[], is_eatout } }] } GET /api/budget/summary // Cache at edge for 60s max Response: { monthly_budget, spent_groceries, spent_eatout, eatout_count_this_week } GET /api/waste/patterns // Only if user has 2+ order cycles done Response: { patterns: [{ ingredient, waste_count, suggestion }] }
On User Action
POST /api/cart/build // Triggered by "Add ingredients" button Body: { template_ids: [string], date: string } POST /api/cart/add-to-instamart // Calls Swiggy MCP — ALWAYS server-side Body: { items: [{name, qty, unit}] } POST /api/voice/parse // Voice → dish name (after speech-to-text) Body: { transcript: string }
Next.js Route Handler Example
// app/api/meal-plans/current/route.ts import { auth } from '@clerk/nextjs' export async function GET() { const { userId } = await auth() // userId from JWT — never from body if (!userId) return Response.json( { error: 'Unauthorized' }, { status: 401 } ) const plan = await db.query.mealPlans.findFirst({ where: eq(mealPlans.userId, userId), // ✓ with: { slots: { with: { template: true } } } }) return Response.json(plan) }

users id, clerk_id, name, goal, diet_type monthly_budget, household_size eatout_per_week, exclusions[] meal_plans id, user_id, week_start meal_plan_slots id, meal_plan_id, day_of_week (1–7) meal_type ENUM(breakfast, lunch, dinner) template_id, is_eatout BOOL templates (read-only on this screen) id, dish_name, tags[], fork_count orders_log user_id, ordered_at, total_amount source ENUM(instamart, food) waste_log user_id, ingredient_name waste_level ENUM(none, some, most) logged_at

Common Mistakes — Fix Before They Happen
  • N+1 query: Never fetch templates per slot individually. Use with: { template: true } in a single Drizzle query.
  • Loading all 7 days: Dashboard fetches TODAY only. Week strip is cosmetic — lazy-load the other 6 days on hover/tap.
  • Stale budget: Budget ring can show 60s-old data (edge cache). Invalidate immediately after an Instamart order is placed.
  • Voice on page load: Never call getUserMedia on mount. iOS Safari silently ignores it; Chrome shows a permission prompt users didn't expect. Only request on explicit button tap.
  • Timezone bug: week_start must use the user's local timezone for day-of-week lookup. Server is UTC — always pass Intl.DateTimeFormat().resolvedOptions().timeZone from the client.
  • Empty state: New users have no meal plan. Show "Build your first plan" CTA inline — never render empty card slots.
  • Race on edit: If user edits plan on web while mobile is viewing, the mobile cache won't update. Add a 30s poll or SWR revalidation on window focus.
  • Waste nudge flash: Only show the waste nudge after 2+ completed restock cycles. Checking on first load makes it appear on day 1.
Performance Targets
  • Dashboard initial load: <1.2s LCP on 4G India (typical Swiggy target)
  • Budget ring SVG: rendered server-side with known percentage, no layout shift
  • Meal cards: skeleton loaders (orange at 8% opacity) until API responds
  • Voice button: shows "listening…" state within 80ms of tap (UI must respond before browser responds)
Authentication & Authorization
  • Clerk JWT: Every API route calls auth() from @clerk/nextjs/server. If userId is null, return 401 immediately — do not proceed.
  • Row-level security: Every Drizzle query includes where: eq(table.userId, userId) using the ID from the JWT, never from the request body or URL params.
  • Swiggy MCP key: API key stored in .env.local as SWIGGY_MCP_API_KEY. Never prefixed with NEXT_PUBLIC_. Only called from /api/cart/add-to-instamart — never from browser.
Data Exposure
  • Budget is PII-adjacent: Never log monthly_budget or total_amount in error messages, Sentry traces, or console logs. Use masked values (e.g. "budget:present") in logs.
  • Voice transcript: Speech-to-text output goes to /api/voice/parse. Sanitize with a strict allowlist before any DB lookup — no raw SQL interpolation.
  • Waste patterns: Only return patterns for the authenticated user. Aggregate query must have WHERE user_id = $1 before GROUP BY.
Rate Limits & Headers
// middleware.ts — apply to all /api routes import { ratelimit } from '@/lib/ratelimit' const limits = { '/api/budget/summary': 100, // per min '/api/voice/parse': 20, // per min '/api/cart/*': 10, // per min } // Required response headers X-Content-Type-Options: nosniff X-Frame-Options: DENY Strict-Transport-Security: max-age=31536000 Content-Security-Policy: script-src 'self'
Input Validation
  • All API inputs validated with Zod before touching the DB
  • Voice transcript: max 200 chars, strip non-alphanumeric except spaces
  • Template IDs: validate as UUID format before query
  • Date params: validate as ISO date string, reject if >30 days in past
Swiggy DS Rules — Dashboard Specific
  • Orange usage: Only on voice button, budget ring fill, "Add to Instamart" buttons, active nav link, restock tag, eat-out dots. Never as card background, heading colour, or decoration.
  • Cards: Background #FFFFFF, border 1px solid #E9E9EB, border-radius 8px, no box-shadow. Shadow is reserved for modals and dropdowns only.
  • Touch targets: All interactive elements minimum 44px height. Voice button: 48px on desktop, 56px on mobile.
  • Typography: Charcoal #282C3F for all headings and primary data. Muted #686B78 for labels, from-template text, meta info. Never pure black (#000) on white.
  • Meal card CTA: "Add ingredients to Instamart" — not "Add to cart" (be specific). Button text must be exact — same label appears in cart confirmation.
  • Week strip: Today pill is orange fill with white text. Done days show a green dot (not full colour fill). Future days show a grey dot. Eat-out days show a yellow dot.
  • Budget ring: SVG circle, not a CSS progress bar. Percentage shown in the ring centre. Legend below: two dots (spent orange, remaining grey).
  • Voice button state: Default → Listening (pulse animation on mic circle) → Processing (spinner) → Result (dish name appears). Never show a modal for voice — result shows inline in hero.
  • Mobile FAB: Orange circle, 52px, positioned bottom-right above tab bar. Triggers the same voice flow as the desktop voice button.
  • Empty states: Meal slot with no template → show "+ Add a meal" in muted text, no empty white card.
Accessibility
  • Voice button: aria-label="Voice order — say a dish name", role="button"
  • Budget ring SVG: role="img" with <title>Budget: 43% spent</title>
  • Week strip day pills: aria-label="Wednesday 2 July, today" on active day
  • All colour contrast ratios: minimum 4.5:1 for body text (charcoal on white = 10.5:1 ✓)
  • Nudge alert: role="alert" so screen readers announce waste pattern on load
