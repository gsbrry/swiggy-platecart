Dev Guide ONBOARDING
Only one API call — on step 5 "Complete"
POST /api/users/onboarding Body: { goal: "loss" | "gain" | "maintain", diet_type: "veg" | "nonveg" | "vegan" | ..., household_size: 1–4, monthly_budget: integer // ₹ exclusions: string[] // max 20 } 201: { userId, onboarding_complete: true } 400: { errors: ZodError[] } 409: Onboarding already complete
Steps 1–4: client-side only (localStorage)
// Persist draft on each step change localStorage.setItem('ob_draft', JSON.stringify({ step: currentStep, goal, diet, household, budget, exclusions })) // Clear after successful POST localStorage.removeItem('ob_draft')
users table — onboarding fields
goal goalEnum // nullable until done diet_type dietTypeEnum household_size integer monthly_budget integer // ₹/month exclusions text[] // ingredient names onboarding_done boolean // default false
Zod validation
z.object({ goal: z.enum(['loss','gain','maintain']), diet_type: z.enum(['veg','nonveg',...]), household_size: z.number().int().min(1).max(8), monthly_budget: z.number().int() .min(1000).max(50000), exclusions: z.array(z.string()).max(20) })
Critical bugs to prevent
  • Do NOT write to DB on steps 1–4. Only POST on step 5 completion.
  • Persist all step data to localStorage — browser refresh kills state otherwise.
  • Return 409 if onboarding_done is already true. Never silently overwrite.
  • Budget field: validate ₹1,000 minimum — users enter "500" or "50" accidentally.
  • Skip = still marks onboarding_done:true with sensible defaults (goal:maintain, diet:veg, hh:1, budget:5000). Never leave it false — causes infinite redirect loop.
  • Exclusions: validate each string against a server-side allowlist. Free-text breaks template filtering.
Auth flow
  • User completes Clerk sign-up BEFORE onboarding. JWT available on all API calls.
  • POST /api/users/onboarding: validate auth() server-side before any DB write.
  • Clerk webhook (user.created) creates minimal row (clerk_id only). Onboarding POST fills the rest.
Data privacy
  • Health goal + diet = sensitive. Exclude from Sentry and Vercel logs.
  • Exclusions allowlist prevents injection via crafted strings.
  • Budget never returned in unauthenticated API responses.
Swiggy DS rules for this screen
  • Selection cards: 1.5px border, orange on select. Never shadow on cards.
  • Continue: disabled = white fill + orange border + orange text. Enabled = full orange fill.
  • Progress: 5 equal segments, 5px height, 5px gap, fill=orange, unfill=#E9E9EB.
  • Check indicator: 20px circle, orange fill, white ✓, only visible when selected.
  • Skip: underlined muted text only. Never a button or chip shape.
  • Back button: disabled on step 1. Muted gray on steps 2–5. Never orange.
  • Step 5 (Exclusions): Continue always enabled. Having no exclusions is valid.
  • Step 6 (Complete): Replace Continue with "Go to Dashboard →" in the nav area. Hide skip link.
